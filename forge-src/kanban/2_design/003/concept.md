## Цель

Определить назначение, структуру и интеграцию файла `codegen.md` — правил, по которым ИИ-агент транслирует спецификацию из `forge-src/` в исходный код.

---

## Что такое `codegen.md`

`codegen.md` — файл в `forge-src/`, который описывает **правила трансляции спецификации в код**. Он отвечает на вопрос: «Как именно ИИ-агент должен генерировать код из описаний?»

### Аналогии

| Аналог | Что настраивает | `codegen.md` настраивает |
|--------|-----------------|--------------------------|
| `Cargo.toml` | Зависимости, профиль сборки | Зависимости, профиль генерации |
| `.clang-format` | Стиль кода C/C++ | Стиль генерируемого кода |
| `tsconfig.json` | Опции компилятора TypeScript | Опции «транслятора» (ИИ-агента) |
| `Makefile` | Правила сборки | Правила генерации и проверки |

## Структура `codegen.md`

```markdown
# Code Generation Rules

## Цель
Правила, по которым ИИ-агент генерирует исходный код из спецификации в forge-src/.

## Порядок чтения (входные данные)
1. concept.md — что строим
2. tech_stack.md — на чём строим
3. struct.md — как организованы модули
4. rules.md — стандарты кодирования
5. codegen.md — этот файл (правила генерации)
6. Текущая задача из kanban/ — что делать сейчас

## Язык и фреймворки
(конкретные версии, библиотеки — детализация tech_stack.md)

## Архитектурные паттерны
(какие паттерны применять, какие — нет)

## Структура генерируемого кода
(директории, нейминг файлов, организация модулей)

## Процесс генерации
1. Прочитать входные данные
2. Спланировать изменения
3. Сгенерировать код
4. Написать тесты
5. Проверить компиляцию
6. Запустить тесты

## Ограничения
- Не использовать библиотеки не из tech_stack.md
- Не нарушать структуру из struct.md
- Не генерировать код вне описанной области
- Каждая новая функциональность = тест

## Тестирование
(обязательные тесты, coverage, что тестировать)

## Стиль кода
(форматирование, нейминг, комментарии)
```

## Интеграция с `forge init`

При `forge init` создаётся базовый шаблон `codegen.md` из `src/templates/codegen.md`.

### Логика генерации

1. `forge init` копирует `src/templates/codegen.md` → `forge-src/codegen.md`
2. Шаблон содержит заголовки секций и комментарии-подсказки
3. Пользователь (или `forge wrap`) заполняет секции под конкретный проект
4. ИИ-агент читает `codegen.md` при генерации кода

### Шаблон для Rust-проектов (по умолчанию)

Шаблон в `src/templates/codegen.md` предзаполнен для Rust:
- Язык: Rust
- Сборка: `cargo build`
- Тесты: `cargo test`
- Линтер: `cargo clippy`
- Форматирование: `cargo fmt`

### Для других языков (будущее)

При `forge init --lang c` или `forge init --lang python` — другой шаблон:
- C: `cmake`, `gcc`, `ctest`
- Python: `pytest`, `ruff`, `mypy`

## Взаимодействие с другими файлами `forge-src/`

| Файл | Связь с `codegen.md` |
|------|----------------------|
| `concept.md` | `codegen.md` не противоречит целям проекта |
| `tech_stack.md` | `codegen.md` детализирует: версии, флаги компилятора |
| `struct.md` | `codegen.md` ссылается на структуру модулей |
| `rules.md` | `codegen.md` дополняет: стиль, паттерны, процесс |
| `kanban/` | Задачи в kanban выполняются по правилам из `codegen.md` |

### Принцип: `rules.md` vs `codegen.md`

- **`rules.md`** — стандарты кодирования для **человека** (DRY, KISS, style)
- **`codegen.md`** — правила генерации для **ИИ-агента** (процесс, паттерны, проверки)

Разделение нужно, потому что человек и ИИ по-разному работают с кодом:
- Человеку: «пиши просто, не дублируй»
- ИИ: «прочитай 5 файлов, спланируй, сгенерируй, скомпилируй, протестируй»

## Команда `forge generate` (будущее)

```bash
# Сгенерировать код по спецификации
forge generate

# Сгенерировать конкретную задачу
forge generate --task 005

# Сгенерировать с указанием модели
forge generate --model claude-sonnet-4-20250514

# Проверить, что код соответствует спецификациям (dry-run)
forge generate --check
```

### Процесс `forge generate`

1. Чтение `forge-src/` (concept, tech_stack, struct, rules, codegen)
2. Чтение задачи из `kanban/4_in_progress/`
3. Формирование промпта с контекстом
4. LLM-вызов через `src/llm/`
5. Парсинг ответа (код, тесты, файлы)
6. Запись файлов в проект
7. `cargo build` / `cargo test` — проверка
8. Отчёт: что создано, что изменено, статус проверки

## Решения по открытым вопросам

| Вопрос | Решение | Обоснование |
|--------|---------|-------------|
| Имя файла | `codegen.md` | Короткое, в стиле `concept.md` / `struct.md` |
| Обязательный? | **Да**, создаётся при `forge init` | Единый контракт для ИИ-агента |
| Шаблон в `src/templates/`? | **Да**, `src/templates/codegen.md` | Как и `agent_readme.md` |
| `rules.md` или `codegen.md`? | **Оба**, разделение по аудитории | `rules.md` для человека, `codegen.md` для ИИ |
| Язык шаблона по умолчанию | **Rust** (текущий стек forge) | Forge написан на Rust |
| Поддержка других языков | **Phase 2**, через `--lang` | Сначала довести Rust, потом расширять |

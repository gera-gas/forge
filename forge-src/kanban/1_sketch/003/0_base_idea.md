# Архитектурное разделение ролей в экосистеме Forge

## Введение

Forge — CLI-утилита, которая управляет структурированными описаниями проекта в `forge-src/`. Эти описания служат **спецификацией** для ИИ-агентов: контекстом для работы и основой для генерации кода.

Ключевая парадигма: **`forge-src/` файлы — это спецификация, а не исходный код.** Код на языке программирования — одна из возможных реализаций этой спецификации. ИИ-агент выступает «транслятором» спецификации в реализацию.

---

## Роли компонентов

| Компонент | Роль | Аналог | Фаза |
|-----------|------|--------|------|
| **forge CLI** | Менеджер спецификаций — создаёт и поддерживает `forge-src/` | IDE для описаний | MVP (сейчас) |
| **VSCode Extension** | GUI-редактор спецификаций — Kanban-доска, формы | GUI для описаний | Phase 1 |
| **ИИ-агент** | Транслятор спецификации → код | «Компилятор» (недетерминированный) | Phase 2 |
| **Cloud/Sync** | Синхронизация для команд | Remote storage | Phase 3+ (отложено) |

## Зафиксированные решения

| # | Вопрос | Решение | Обоснование |
|---|--------|---------|-------------|
| 1 | Облако / сетевой диск | **Отложить до Phase 3+** | Git решает синхронизацию для соло-разработчика. Облако имеет смысл только для команд (Pro tier) |
| 2 | Один инструмент или несколько | **Один бинарник `forge`**, внутреннее разделение на модули | `wrap` и `generate` — обратные операции, делят формат файлов. Разделение = дублирование |
| 3 | `forge-src/` файлы — это исходный код? | **Нет, это спецификация** | ИИ-агент недетерминирован. Описание → одна из возможных реализаций, не единственная |
| 4 | `codegen.md` | **Создать как обязательный файл** | Правила трансляции спецификации в код. Шаблон в `src/templates/codegen.md` |
| 5 | ИИ-агент — компилятор? | **Нет, транслятор** | Компилятор детерминирован (тот же вход → тот же выход). ИИ — нет (тот же вход → разные варианты) |

## Эволюция архитектуры

```
Phase 1 (MVP):
  forge CLI (менеджер спецификаций)
  → VSCode Extension (GUI-редактор, вызывает CLI)

Phase 2:
  forge CLI
  ├── context/   (управление спецификацией: init, wrap, task)
  ├── codegen/   (генерация кода: generate)
  └── llm/       (LLM-интерфейс: общий для wrap и generate)
  + forge agent  (ИИ-агент как подкоманда)
  + Multi-agent  (Arch / Dev / Ops)

Phase 3:
  Выделить forge-core как библиотеку
  ├── forge         (CLI-бинарник)
  ├── forge-agent   (бинарник агента)
  └── forge-vscode  (VSCode extension, использует forge-core)

Phase 4+:
  + Cloud Sync (backend для команд)
  + Mobile App
  + Paid features (Pro / Enterprise)
```

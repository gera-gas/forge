# Мульти-агентная система (Arch / Dev / Ops)

**Приоритет:** Phase 2  
**Родитель:** [0_base_idea.md](0_base_idea.md)

---

## Цель

Разделение работы ИИ-агента на три роли с разными моделями для оптимизации затрат и качества.

---

## Три роли агентов

### 1. Arch (Архитектор)
- **Модель:** Claude Sonnet / GPT-4o / o3
- **Задачи:**
  - Анализ требований
  - Проектирование архитектуры
  - Принятие решений (какие файлы менять, какой подход)
  - Декомпозиция задач
  - Code review
- **Стоимость:** $$$

### 2. Dev (Разработчик)
- **Модель:** Claude Sonnet / GPT-4o-mini / DeepSeek Coder
- **Задачи:**
  - Написание кода по плану от Arch
  - Рефакторинг
  - Написание тестов
  - Исправление багов
- **Стоимость:** $$

### 3. Ops (Оператор)
- **Модель:** GPT-4o-mini / Haiku / Gemma / локальная
- **Задачи:**
  - Создание/перемещение файлов
  - Git операции (commit, push, branch)
  - Запуск тестов и сборок
  - Форматирование, линтинг
  - Простые шаблонные операции
- **Стоимость:** $

---

## Маппинг ролей на стадии Kanban

| Стадия Kanban | Роль агента | Модель |
|---------------|-------------|--------|
| `1_sketch` | **Arch** | Сильная (рассуждения) |
| `2_design` | **Arch** | Сильная (финализация) |
| `3_todo` | **Arch → Dev** (передача) | Arch декомпозирует, Dev получает план |
| `4_in_progress` | **Dev** + **Ops** | Dev пишет код, Ops коммитит/создаёт файлы |
| `5_done` | **Ops** | Перемещение файла, финальный коммит |

## Оркестратор (Router)

### Вариант A: Правила (без LLM) — РЕКОМЕНДУЕМЫЙ для MVP
- Если операция = git/файловая → Ops
- Если операция = код → Dev
- Если вопрос/решение → Arch

### Вариант B: Классификатор (Phase 3+)
- Маленькая модель (Haiku) определяет тип задачи и маршрутизирует

## Настройки стоимости

```toml
[agents]
arch_model = "anthropic/claude-sonnet-4-20250514"
dev_model = "deepseek/deepseek-coder"
ops_model = "google/gemma-2-9b-it"  # или локальная через Ollama

[agents.cost_limits]
daily_budget = 5.00  # USD
arch_max_per_task = 0.50
dev_max_per_task = 0.30
ops_max_per_task = 0.05
```

## Файлы ролей (Skills)

Каждая роль — отдельный файл:
- `forge/roles/arch.md` — system prompt + инструменты + ограничения
- `forge/roles/dev.md` — system prompt + инструменты + ограничения
- `forge/roles/ops.md` — system prompt + инструменты + ограничения

---

## Преимущества

1. **Экономия до 60-70%** — Ops берёт на себя рутину на дешёвой модели
2. **Качество решений** — Arch не отвлекается на рутину
3. **Конкурентное преимущество** — ни Cline, ни Cursor не делают такое разделение

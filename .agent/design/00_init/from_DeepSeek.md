## Ответы на ваши вопросы

### 1. Где разместить каталоги для ИИ?

Рекомендую **`docs/agent/`** как основной каталог. Почему:

- Не скрытый – виден в репозитории, соответствует стандарту документации.
- Легко находить и редактировать.
- Можно сделать символическую ссылку `.agent -> docs/agent` для совместимости с инструментами, которые ищут `.agent` (например, Cline).

**Для CLI-утилиты:** предложите выбор по умолчанию `docs/agent/` с опцией `--path` для переопределения.

---

### 2. Обернуть текущий проект в описание для ИИ (генерация `concept.md`, `tech_stack.md` и т.д.)

Да, для этого **потребуется внешний ИИ** (LLM), так как нужно осмысленно описать проект. MCP **не обязателен** – достаточно прямого вызова API (OpenAI, Anthropic, локальная модель через Ollama). Алгоритм:

1. Сканируем файловую структуру проекта, определяем язык, фреймворки, зависимости (анализ `Cargo.toml`, `package.json`, `requirements.txt` и т.п.).
2. Собираем контекст: список модулей, ключевые файлы.
3. Отправляем запрос к LLM: «Сгенерируй `concept.md`, `tech_stack.md`, `RULES.md` для проекта на основе следующего описания…».
4. Сохраняем сгенерированные файлы в `docs/agent/`.

MCP пригодится позже для интеграции с Jira/Trello, но не для этой задачи.

---

### 3. Генерация подготовленных шаблонов проектов (например, `proj_name.forge.toml` → CMake/Bazel)

Это расширенная функция. Работает так:

- Пользователь создаёт `myproject.forge.toml` с описанием (имя, язык, структура, зависимости).
- Утилита читает TOML, формирует промпт для LLM: «Сгенерируй CMakeLists.txt для проекта на C++ со следующей структурой…».
- LLM возвращает содержимое файла сборки.
- Утилита сохраняет его.

LLM API достаточно, MCP не нужен. Можно добавить поддержку нескольких форматов сборки.

---

### 4. Поддержка NLP (общение обычным языком)

Реализуется через **интерпретатор команд с использованием LLM**:

- Пользователь пишет: «создай новую задачу на рефакторинг модуля auth».
- Утилита отправляет этот текст в LLM с инструкцией: «преобразуй в JSON команду из нашего набора (create_task, move_task, generate_docs и т.д.)».
- LLM возвращает структурированную команду, утилита выполняет.

Можно использовать небольшую локальную модель (например, Llama 3 8B) для быстрых ответов.

## План разработки CLI-утилиты (согласно нашим стандартам)

Теперь, следуя методологии, мы начинаем с **дизайна**. Я создаю дизайн-документ `design/00_vision.md` для утилиты. Вот его содержание:

```markdown
# Vision: Forge – CLI для управления контекстом ИИ-агентов

## Идея
Утилита `forge` помогает разработчикам создавать и поддерживать структуру `docs/agent/` для любых проектов. Она умеет:
- Инициализировать пустой набор каталогов/файлов.
- Автоматически генерировать описание существующего проекта (через LLM).
- Создавать задачи и управлять Kanban-доской (`todo/in_progress/done`).
- Генерировать файлы сборки (CMake, Bazel и др.) из TOML-спецификации.
- Понимать естественный язык команд.

## Целевая аудитория
Разработчики, использующие ИИ-агентов (Claude Code, Cline, Aider) для помощи в кодинге.

## Основные команды (MVP)
- `forge init` – создаёт `docs/agent/` с минимальной структурой.
- `forge wrap` – анализирует текущий проект и генерирует `concept.md`, `tech_stack.md`, `RULES.md`.
- `forge task add "описание"` – добавляет задачу в `tasks/todo/`.
- `forge task start` – перемещает задачу из `todo` в `in_progress`.
- `forge task done` – перемещает в `done`.

## Расширенные команды (v2)
- `forge template new --lang c --build cmake` – создаёт `project.forge.toml` и генерирует CMakeLists.txt.
- `forge ask "создай задачу на рефакторинг"` – NLP-интерфейс.

## Технологический стек (предварительный)
- Язык: Rust
- Парсинг аргументов: `clap`
- Работа с файлами: `std::fs`, `walkdir`
- HTTP-клиент для LLM API: `reqwest`
- TOML: `toml`
- Markdown-парсинг (минимально): `pulldown-cmark`

## Ограничения
- LLM API требуется для `wrap` и `template` (можно отключить флагом `--no-llm`).
- Начальная версия не поддерживает MCP.

## Следующие шаги
1. Создать задачи в `tasks/todo/` на реализацию MVP.
2. Выбрать LLM API (Anthropic или OpenAI) и добавить ключ через env.
3. Реализовать `forge init` и `forge wrap`.
```

Теперь переходим к созданию задач на основе этого дизайна. Я создам несколько задач в `tasks/todo/`:

**Задача 001: Базовый CLI с командой `init`**
- Создать структуру `docs/agent/` с пустыми папками и файлами-заглушками.
- Поддержать флаг `--path`.

**Задача 002: Команда `wrap` – генерация описания проекта через LLM**
- Сканировать проект (язык, зависимости).
- Отправить запрос к LLM (OpenAI/Anthropic).
- Сохранить `concept.md`, `tech_stack.md`, `RULES.md`.

**Задача 003: Управление задачами (Kanban)**
- Команды `task add`, `task list`, `task start`, `task done`.
- Работа с папками `tasks/todo/`, `in_progress/`, `done/`.

**Задача 004: NLP-интерфейс (команда `ask`)**
- Преобразовывать естественный язык в команды через LLM.
- Выполнять полученную команду.

**Задача 005: Шаблоны проектов (генерация CMake/Bazel)**
- Читать `project.forge.toml`.
- Генерировать файлы сборки через LLM.

Теперь, чтобы следовать нашему процессу, я **создам эти задачи в виде файлов** в `tasks/todo/` (здесь, в чате, я представлю их текстово). Вы можете взять их как основу.

### 1. Ответы на архитектурные вопросы

**1.1. Где расположить каталоги для ИИ?**
Я настоятельно рекомендую вариант **`.agent`** (скрытая папка).
*   **Почему:**
    *   Это стандарт для конфигурационных папок в *nix системах (как `.git`, `.github`, `.vscode`, `.cursor`).
    *   Она не мешает пользователям в файловом менеджере.
    *   Четкое разделение: `docs/` — для людей (пользовательская документация), `.agent/` — для машин (инструкции для ИИ).
    *   **Вариант `docs/agent`** подходит, если вы хотите, чтобы эти инструкции были частью публичной документации, но это редкость.

**1.2. Обернуть текущий проект (Feature #2)**
Да, для этого нужен внешний ИИ.
*   **Нужен ли MCP?** Model Context Protocol (MCP) — это отличный инструмент, если мы хотим сделать из утилиты сервер, к которому могут подключаться другие агенты. Для самой генерации описания MCP не обязателен, но полезен для интеграции. Для начала достаточно API-клиента к LLM.
*   **Как это работает:** Утилита сканирует структуру файлов, считывает ключевые файлы (`README`, импорты, основные классы) -> отправляет в LLM с промптом "Сгенерируй `.agent/concept.md` и `.agent/tech_stack.md` на основе этого кода".

### 2. Применяем стандарт: Создаем Дизайн и Задачи

Сейчас мы выступаем в роли Инициатора Проекта. Создаем структуру для нашей утилиты (назовем её условно `forge-agent`).

#### Шаг 1: Создаем `design/00_vision.md`

Согласно нашему же стандарту, начинаем с видения.

```markdown
# Vision: Forge Agent CLI

**Дата:** 2024-05-21
**Статус:** Draft

## Идея
CLI-утилита для управления контекстом ИИ-агентов в проектах. Она стандартизирует папку `.agent/`, позволяя разработчикам быстро "поднять" контекст для работы с LLM, а также "обернуть" существующий проект в понятное для ИИ описание.

## Цели
1. Стандартизировать взаимодействие между человеком и ИИ через файловую систему.
2. Ускорить онбординг ИИ в новый проект (с 0 до понимания контекста за 1 команду).
3. Автоматизировать рутину: создание шаблонов, генерация описаний кода.

## Ключевые фичи (MVP)
1. **Init:** Генерация пустой структуры `.agent/` с базовыми Markdown файлами.
2. **Wrap:** Анализ существующего кода (через LLM) и генерация `.agent/concept.md`, `.agent/STRUCT.md`.
3. **Template (Future):** Генерация шаблонов проектов (C/C++/Rust) с готовым контекстом.

## Технологический стек (Предварительно)
- **Язык:** Rust (для скорости, безопасности и удобства дистрибуции единственным бинарником).
- **Парсер аргументов:** `clap`.
- **LLM Client:** `async-openai` или `reqwest` (для вызова API).
- **Файловая система:** `std::fs`, `walkdir`.
```

```markdown
# Task: Реализовать команду `init`

## Описание
Создать базовую структуру каталогов `.agent/` и файлы по умолчанию, если они отсутствуют.

## Требования
1. Команда: `forge-agent init`.
2. Создавать папки: `.agent/design`, `.agent/specs`, `.agent/tasks/todo`, `.agent/workflows`.
3. Создавать файлы: `README.md`, `concept.md` (пустой шаблон), `tech_stack.md` (пустой), `workflows/agent.md` (дефолтный).
4. Если папка `.agent` уже существует — спрашивать подтверждение на перезапись (или пропуск).
5. Использовать `clap` для парсинга аргументов.

## Критерии приемки
- [ ] `cargo run -- init` создает структуру файлов.
- [ ] Файлы содержат шаблонный текст из нашего стандарта.
```

**Файл:** `.agent/tasks/todo/002_wrap_command.md`
```markdown
# Task: Реализовать команду `wrap` (Анализ проекта)

## Описание
Анализировать существующий код проекта и генерировать описание в `.agent/` с использованием LLM.

## Требования
1. Команда: `forge-agent wrap --source ./src`.
2. Чтение файловой структуры (tree).
3. Выборка ключевых файлов (основываясь на эвристиках: `main.rs`, `lib.rs`, `Cargo.toml`, `README.md`).

5. Запись полученных файлов в `.agent/`.

## Технические детали
- Понадобится API Key (брать из ENV: `OPENAI_API_KEY`).
- Использовать модель `gpt-4o` или аналоги.

## Критерии приемки
- [ ] Утилита корректно отправляет контекст в LLM.
- [ ] LLM возвращает валидный Markdown.
- [ ] Файлы создаются в нужных местах.
```

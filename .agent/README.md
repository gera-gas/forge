# Agent Context Directory

Эта директория содержит всю конфигурацию и контекст для ИИ-агентов (Claude Code, Cline, Aider и др.).  
Агент должен начинать работу с чтения этого файла.
Чем-то похоже на Cline memory_bank.

## Структура
```text
.agent/
├── README.md     # Этот файл (точка входа)
├── concept.md    # Концепция, цели, ограничения проекта (живой документ)
├── tech_stack.md # Технологический стек, версии, зависимости
├── rules.md      # Стандарты кодирования: DRY, KISS, тесты, code style
├── struct.md     # Модульная структура проекта (кто за что отвечает)
├── arch.md       # Архитектурные решения (ADR) – добавляется по мере необходимости
│
├── workflows/ # Пошаговые инструкции для типовых задач
│   ├── agent.md # Как агенту выполнять задачи (порядок чтения, создание задач)
│   ├── git.md   # Git-процесс: ветки, коммиты, PR
│   └── pm.md    # Управление проектом (Jira/Trello, приоритеты) – опционально
│
├── design/ # Черновики дизайна (временные файлы, обсуждения)
│   └── ... # Любые .md файлы, например, 2025-04-08_auth_flow.md
│
├── specs/ # Утверждённые технические задания на фичи
│   └── feature_xyz.md
│
├── kanban/        # Kanban-доска со стадиями дизайна и реализации
│   ├── 0_backlog/      # Отложенные задачи
│   ├── 1_sketch/       # Идеи, user stories, наброски
│   ├── 2_design/       # Утверждённый дизайн, ТЗ
│   ├── 3_todo/         # Технически проработанные задачи, готовые к коду
│   ├── 4_in_progress/  # В работе (не более одной)
│   └── 5_done/         # Завершённые задачи
│
├── tasks/         # ⚠️ DEPRECATED – используйте kanban/ для новых задач
│   ├── backlog/     # Отложенные / ожидают дизайна или уточнения
│   ├── todo/        # Готовы к работе (приоритизированы)
│   ├── in_progress/ # Взято в работу (не более 1-2 задач)
│   └── done/        # Завершённые задачи (история)
│
└── glossary.md # Термины проекта – опционально
```

## Обязательные файлы (создаются при инициализации проекта)

- **`concept.md`** – 1-2 страницы: зачем проект, что делает, основные ограничения.
- **`tech_stack.md`** – языки, фреймворки, базы данных, версии (пример ниже).
- **`rules.md`** – принципы (DRY, KISS, SOLID), требования к тестам, code style.
- **`workflows/agent.md`** – как агенту читать файлы и выполнять задачи.
- **`workflows/git.md`** – минимальные правила коммитов и PR.
- **`tasks/todo/`** – пустая папка.

## Порядок чтения агентом (перед началом работы)

1. **`README.md`** (этот файл) – чтобы понять структуру.
2. **`concept.md`** – понять цели и ограничения.
3. **`tech_stack.md`** – узнать технологии.
4. **`rules.md`** – узнать стандарты кода.
5. **`struct.md`** (если есть) – понять модули.
6. **`workflows/agent.md`** – как работать с задачами.
7. **Текущая задача** из `kanban/4_in_progress/` (или первая из `kanban/3_todo/`).

Остальные файлы (`arch.md`, `workflows/git.md`, `specs/`, `design/`) загружаются **по необходимости** (например, `git.md` – только перед коммитом).

## Как начать новый проект (пошагово)

1. **Создайте директорию** `.agent/` или `docs/agent/`в корне проекта.
2. **Скопируйте этот README.md** в неё.
3. **Создайте минимальные файлы**:
   - `concept.md` – напишите черновик идеи (можно начать с одного абзаца).
   - `tech_stack.md` – перечислите планируемые технологии.
   - `rules.md` – скопируйте базовые правила (см. пример ниже).
   - `workflows/agent.md` – опишите порядок работы агента (см. шаблон).
   - `workflows/git.md` – укажите хотя бы формат коммитов.
4. **Создайте папки** `design/`, `specs/`, `tasks/todo/`, `tasks/in_progress/`, `tasks/done/`.
5. **Создайте первый дизайн-документ** – положите в `design/` файл с именем `concept_draft.md` или `00_vision.md`.  
   Это будет исходная идея, которую вы потом отредактируете и, после утверждения, перенесёте в `concept.md` и `specs/`.

## Пример содержимого `tech_stack.md`

```text
# Технологический стек

- **Язык**: Rust 1.85+
- **Фреймворк**: Actix-web (для HTTP)
- **БД**: PostgreSQL 15 + SQLx
- **Миграции**: refinery
- **Тестирование**: cargo test + proptest
- **Линтер**: clippy, rustfmt
- **CI**: GitHub Actions
```

## Пример содержимого rules.md (минимальный)

```text
# Стандарты кодирования

- **DRY** – не дублируй логику.
- **KISS** – предпочитай простые решения.
- **Тесты** – обязательны для новой функциональности.
- **Code style** – стандартный rustfmt (макс. длина строки 100).
- **Обработка ошибок** – использовать `anyhow` для бинарников, `thiserror` для библиотек.
```

## Пример содержимого workflows/agent.md

```text
# Рабочий процесс для агента

1. Прочитай `README.md`, `concept.md`, `tech_stack.md`, `rules.md`.
2. Проверь `tasks/in_progress/`. Если есть задача – работай над ней. Если нет – возьми первую из `tasks/todo/` и перемести в `in_progress/`.
3. Перед началом реализации задачи прочитай `struct.md` (если есть) и соответствующие `specs/`.
4. После выполнения:
   - Обнови файл задачи (добавь дату завершения).
   - Перемести его в `tasks/done/`.
   - Сделай коммит с сообщением `feat: #задача описание`.
   - Если нужен PR – создай его и запроси ревью.
5. Для Git-операций следуй `workflows/git.md`.
```

## Файлы, добавляемые по мере роста проекта

Проект начинается с малого. Со временем вы добавите:

| Файл | Когда добавлять | Описание |
|------|----------------|----------|
| `struct.md` | Когда модулей >3 | Модульная структура проекта (кто за что отвечает) |
| `arch.md` | При первых значимых ADR | Архитектурные решения (Architecture Decision Records) |
| `deploy.md` | При настройке CI/CD | Инструкции по сборке, деплою, окружениям (dev/staging/prod) |
| `specs/` | При крупных фичах | Утверждённые технические задания, требующие детального описания |
| `glossary.md` | При специфической терминологии | Словарь терминов проекта (domain-specific language) |
| `workflows/pm.md` | При подключении Jira/Trello | Интеграция с системами управления задачами |

> **Важно:** Не создавайте всё сразу. Итеративное наполнение – ключ к поддержанию порядка.  
> При добавлении нового файла обновите этот README.md и добавьте строку в таблицу выше.
